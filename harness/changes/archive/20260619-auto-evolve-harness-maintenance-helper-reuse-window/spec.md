# Spec: auto-evolve-harness-maintenance-helper-reuse-window

## Goal

Complete the pending Harness evolution generated by the latest five maintenance helper-reuse archives without adding unnecessary durable rules.

## Users

- Future AHO agents using Harness evolution evidence and current handoff docs.
- AHO maintainers evaluating whether the helper-reuse convergence window reveals a new process rule.

## Acceptance Criteria

- AC-001: The pending candidate window is evaluated from `harness/evolution/pending.md`.
- AC-002: `harness/evolution/proposals/20260619-maintenance-helper-reuse-window-keep.md` records the candidate window, recommendation, independent review, Experience Retention Scan, Documentation Entropy, and Boundaries.
- AC-003: The Experience Retention Scan covers `AGENTS.md`, `docs/STATUS.md`, `docs/ECL.md`, templates if relevant, `docs/CURRENT-DEVELOPMENT-PLAN.md`, and `docs/AGENT-DEVELOPMENT-OS.md`.
- AC-004: The result is recorded in `harness/evolution/results.tsv` and `harness/evolution/state.json` by `scripts/harness-evolve.ps1 mark-complete`.
- AC-005: `harness/evolution/pending.md` is removed after `mark-complete`.
- AC-006: No new Harness rule, template, lint, product runtime, Workbench, Scheduler, Goal Loop, ToolPolicy, human-gate, source, reference, or README change is introduced.
- AC-007: `AGENTS.md` and `docs/STATUS.md` are aligned during active evolution and after close.

## Non-Goals

- Promote helper-reuse implementation details into ECL or current docs.
- Change product runtime behavior.
- Change Harness scripts, thresholds, candidate selection, or evolution automation.
- Rewrite roadmap/product docs beyond stale handoff correction.
- Stage or modify unrelated `README.md`.

## Constraints

- Pending evolution is not auto-applied; it must use proposal, independent review, validation, results logging, and `mark-complete`.
- `keep` means retaining existing current rules as sufficient durable Harness memory.
- Current docs should remain compact; detailed helper-reuse history stays in archive summaries and the evolution proposal.

## Risks

- Adding another overlapping ECL rule could increase documentation entropy without improving future behavior.
- Failing to retire stale active handoff wording after the product close would mislead the next agent.
