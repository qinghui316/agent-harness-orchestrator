# Spec: auto-evolve-harness-real-codex-acceptance-window

## Goal

Handle the pending Harness evolution window generated from the latest five
archived changes and leave future agents with compact, behavior-changing
guidance.

## Users

- Future AHO agents handling real acceptance, Workbench verification, and
  Harness closeout.
- Maintainers reviewing whether archived experience should become durable
  Harness memory.

## Acceptance Criteria

- AC-001: The five candidate archive summaries are evaluated against existing
  ECL, current-plan, and documentation entropy rules.
- AC-002: A proposal records an Experience Retention Scan with Promote,
  Retain, Merge, Retire, and Archive-only decisions where applicable.
- AC-003: An authorized subagent performs read-only independent review and its
  recommendation, score, and limitations are recorded.
- AC-004: Any promoted rule is narrow, current, and tied to repeated archive
  evidence; otherwise the evolution records a noop rationale.
- AC-005: The pending evolution is completed through `results.tsv` and
  `scripts/harness-evolve.ps1 mark-complete`; `pending.md` is removed by the
  script.
- AC-006: Handoff docs agree on active/pending/latest archive state after
  close and do not copy archive ledger detail into current docs.

## Non-Goals

- Implement product behavior.
- Implement full-auto, scheduler loops, parallel executor behavior, or remote
  landing.
- Add a new evidence family or broad review template section when one compact
  ECL rule is sufficient.
- Rewrite historical archives.

## Constraints

- `harness/changes/INDEX.json` must be regenerated by script, not hand edited.
- Subagent review is advisory only; it does not own the ECL lifecycle,
  canonical docs, or `mark-complete`.
- Current docs should retain only guidance that changes present agent behavior.

## Risks

- Over-promoting one-off acceptance details into permanent process text.
- Leaving a repeated real-acceptance or verification lesson only in archive
  summaries where future agents will miss it.
- Expanding `AGENTS.md` or `docs/STATUS.md` into another archive ledger.
