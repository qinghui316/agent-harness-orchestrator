# Spec: Phase 10G Goal Loop Continuation Brief Evidence

## Problem

Phase 10F records continuation state and control constraints inside
`GoalLoopIteration`, but the next main Agent turn still lacks a durable,
AHO-owned brief that says how to continue from current evidence without
shrinking the user's long-running objective or bypassing Harness gates.

Codex `goal` has a true runtime continuation system. AHO should not copy that
runtime. AHO needs only an evidence artifact that a future turn can read after
it re-reads the repository and selected Change.

## Scope

- Add a versioned `GoalLoopContinuationBrief` JSON/Markdown artifact.
- The brief is generated by the existing `planning.goal-loop.evaluate` action.
- The brief is derived from current `GoalLoopDecision` and the just-written,
  latest `GoalLoopIteration`.
- The artifact records non-execution authority, source evidence refs,
  recommended-action snapshot, completion audit, resume preconditions,
  forbidden actions, and explicit instructions to re-read current evidence.
- Workbench decision/audit payload may include the brief id/ref.

## Acceptance Criteria

- AC-001: Docs record Phase 10F archived, Phase 10G active, and no stale
  Phase 10F active claim.
- AC-002: `GoalLoopContinuationBrief` is owned by `src/goal-loop/` with clear
  type/schema/path/repository/rendering boundaries.
- AC-003: `planning.goal-loop.evaluate` writes a decision, iteration, and
  continuation brief without adding a new action.
- AC-004: The brief is derived from a re-read latest iteration and fails closed
  if latest iteration scope or execution state is invalid.
- AC-005: The brief states that it is non-executing evidence, not workflow
  truth, not execution authorization, and not a hidden continuation prompt.
- AC-006: Recommended action, if present, remains a snapshot only and must be
  confirmed through its own Harness gate.
- AC-007: No scheduler/worker/IntegrationCheck/apply/close/source mutation
  artifacts are created by Goal Loop evaluation.
- AC-008: Workbench handler remains a thin caller/recorder and does not own
  Goal Loop domain logic.
- AC-009: New `src/goal-loop/*` code does not import Workbench, server, web,
  CLI command modules, broad facades, or execution/start/apply/close modules.
- AC-010: Existing `GoalLoopDecision` and `GoalLoopIteration` compatibility is
  preserved.
- AC-011: Product and Harness verification pass, or any pre-existing failure is
  clearly recorded.
- AC-012: `README.md` remains unrelated and untracked.

## Assumptions

- Phase 10G is evidence hardening, not a product runtime controller.
- Future Goal Loop controller behavior, if ever added, must be a separate
  phase with explicit owner module, ToolPolicy/human gate handling, and tests.
- Codex goal source is a reference for continuation discipline, not an AHO
  workflow-truth replacement.
